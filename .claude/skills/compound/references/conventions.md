# Compounding knowledge store - conventions

The contract for `lessons/{category}/{slug}.md`. Read this before writing or updating a learning.

## File layout

- One learning per file: `lessons/{category}/{slug}.md`
- `lessons.md` at repo root is the **index** - its `## Index by category` section is generated by
  `scripts/reindex.py`, never hand-edited. The protocol prose above that marker is hand-authored.

## Frontmatter schema (required)

```yaml
---
slug: kebab-case-id            # matches the filename, no date suffix
category: voice                # one of the categories below
title: "One-line imperative rule statement"
applies_to: [skill-or-scope, another-scope]   # who must obey this; use `all` for universal
tags: [keyword, keyword]       # search terms - error strings, module names, concepts
problem_type: convention       # see enum below
date: 2026-06-29               # creation date; the canonical date lives here, not in the filename
---
```

**YAML safety (the failure mode that breaks the index):** if the `title` contains a double quote,
single-quote the whole value (`title: 'Never open with "I"'`). Never put an unquoted ` #` or `: `
in a scalar value. No em dashes anywhere - this store obeys the house voice rules it documents.

## Categories

Pick the existing category that fits. Create a new one only when no existing category is even close
(and add its description to `CATEGORIES` in `scripts/reindex.py` so the heading renders).

| Category | Scope |
|----------|-------|
| `voice` | tone, word choice, banned phrases, em dashes, how Gen sounds |
| `hooks` | opening lines and first impressions |
| `structure` | post architecture and content shape |
| `aeo` | structuring content for AI citation + factual accuracy (no fabricated stats) |
| `html-site` | visual rendering, accessibility, deploy/crawler config |
| `client-context` | loading and respecting client-specific source material |
| `workflow` | how the ops system runs, gates, repo hygiene, self-improvement |
| `youtube` | competitor research, outlier scoring, packaging |
| `audit-positioning` | grounding competitive work in real data |
| `notion` | master DBs, portals, schema mutations, data integrity |
| `cost-routing` | which model runs where vs quality |
| `security` | handling credentials on commit/push/move |

## problem_type enum

- `voice-drift` - the output sounded wrong (banned phrase, slop, hedging)
- `convention` - a team-agreed way of doing something, captured so it survives
- `factual-accuracy` - a claim was fabricated or misattributed
- `bug` - a tool/script/page produced broken behavior
- `workflow` - a process gap or sequencing rule
- `data-integrity` - a data store could be corrupted or silently desynced
- `security` - a credential-handling risk
- `cost-quality` - a model/cost decision that affected output quality

## Body structure

```markdown
# {title}

**Problem:** what went wrong, with the concrete symptom (error string, the exact bad output).

**Rule:** the constraint that prevents it next time - specific and falsifiable, not "be careful".

**Why:** (optional) the mechanism, when the rule is non-obvious or counterintuitive.

**Applies to:** the same scopes as `applies_to`, in prose.
```

## Slug rules

- kebab-case, derived from the rule not the symptom (`secret-scan-fail-closed`, not `notion-token-leak`)
- no date suffix - the `date:` field is canonical
- stable: do not rename a slug once other files reference it

## Overlap: update vs create

Before writing, grep the store for the same rule (`grep -rl "<keyword>" lessons/`). Then:

- **High overlap** (same problem, same root cause, same rule already exists): **update** the existing
  file - sharpen the rule, add the new symptom, add a `last_updated:` field. Do not create a duplicate.
- **Moderate overlap** (same area, different angle): create the new file; the two are distinct.
- **Low/none**: create normally.

This is the repo's `audit-before-creating` rule applied to the knowledge store: one location per rule.
