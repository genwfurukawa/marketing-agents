# Methodology

The client-agnostic layer: frameworks that hold across engagements. Anything
specific to one company lives in that company's own `brain/` files, never here.

## The five stages

**CAPTURE.** Get what the team knows out of their heads. Interviews, sales calls,
reviews, support tickets, and an audit of what has already been published. This is
the step most vendors skip, and it is why their output sounds like nobody. Nothing
enters the Brain without a source pointing at where it came from.

**BUILD.** Turn it into a system that runs, then run it. The Brain, a memory every
agent reads from before it makes anything. The Voice, pulled out of existing best
work rather than invented. Drafts come from the queue, not from a blank prompt.

**APPROVE.** Six gates, then one human. The gates run on a different model than the
one that wrote the draft, because a model does not catch what it just rationalized.
This is the only stage where a person is required, which is what makes automating
the other four safe.

**SHIP.** Get it in front of buyers, and record what went out.

**IMPROVE.** Performance feeds back. The Brain gets richer. The people running it
take over more of it each cycle.

**It is a loop, not a line.** Improve feeds Capture. Month twelve is better than
month one because the system kept what worked.

## One loop, two clocks

These are the same five stages as [`../README.md`](../README.md). There is one loop
and one set of names for it, whether you are describing a twelve month engagement or
a Tuesday.

The difference is only the clock. Over months, CAPTURE is an onboarding project and
IMPROVE is a quarterly review. Day to day, CAPTURE is a transcript landing in the
queue and IMPROVE is last week's numbers changing what gets built next. Four loops
(`../loops/`) run these five stages at four different speeds against one shared
Brain.

## The scoring standard

[`visibility-system/citability_score_rubric.md`](../visibility-system/citability_score_rubric.md)
is the six-section, 0 to 100 rubric for grading whether a site is citable by AI
engines. Six sections: the answer test, structure, authority, rivals, presence and
the gate. Use it for a baseline, then re-run it against that baseline rather than
reporting an absolute number.

## What is deliberately not written down here

The order in which to pick the next action, and how to drive it to a publish gate
without a person in the loop. That is orchestration, it is not in this repo, and
the rest of the repo works without it.
